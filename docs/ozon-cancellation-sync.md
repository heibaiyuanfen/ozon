# Ozon 取消件数与订单状态同步修复（2026-10-24）

默认本土店的旧订单缓存停在10月19日，但销量缓存仍每天更新，导致10月19—24日看板把缺失的取消状态显示成0。实际只读请求确认，/v3/posting/fbs/list和/v2/posting/fbo/list均返回HTTP400、code9、obsolete method cannot be used。旧调用链使用let _忽略这两个错误，因而没有告知用户。

正式桌面程序改用 /v4/posting/fbs/list 和 /v3/posting/fbo/list。两个接口均读取顶层postings/has_next/cursor，每页100单，直到has_next=false；不再按旧result/offset结构处理。支持price.amount/currency金额结构，非RUB价格不错误当作RUB精确扣减，缺少准确RUB单价时由净看板沿用明确标注的均价估算。

订单保存和取消事件更新采用同一事务；重复同步不重复计数，取消状态恢复时移除对应取消事件。销量同步中的订单错误现在会上报，并分别记录Seller Orders FBS/FBO日志。

新增posting_sync_coverage按日与FBS/FBO记录同步成功/失败。只有两类订单均在最近24小时内完整读取成功，净看板才把取消件数作为已核对值；否则显示待核对及缓存数量，并提示净销量、净销售额和广告比例暂按缓存估算。界面显示状态核对时间。
