# Ozon RFBS 独立上品工具

这是一个从零实现的独立桌面程序。`参考代码` 中的旧项目仅用于理解业务经验；本目录不导入旧模块，删除参考目录后仍可运行。

## 功能

- 默认打开“自动工作台”，可选择“跟卖模式”或“本地新品模式”。跟卖模式读取指定 Ozon 链接/商品 ID；本地新品模式无需来源链接，直接选择最多 15 张已经制作好的商品图片，第 1 张作为主图。两种模式共用可选的 1688 采购链接、自动 Offer ID、型号名称、人工佣金 ROI/FBP 核价、重量尺寸、人工类目、属性、OSS、Ozon 导入、RFBS 库存和 Excel 产品台账。
- “6. WB 上架”已经接入 Wildberries 官方 API：可保存并测试个人 Token，支持 WB 跟卖和本地新品，读取中文父类目、子类目及实时属性，人工填写 WB 佣金，按目标利润率自动核价，创建新品卡片、上传图片，并设置价格、折扣及卖家仓库存库。程序按卖家货号查询已存在卡片，并在每项外部写操作前后保存 `wb_job.json` 断点；网络中断后继续任务不会盲目重复创建卡片。
- 本地新品图片在任务加入队列时复制到程序数据目录，避免原文件被移动后导致排队任务失效。视觉分析 AI 会先读取这些图片，再基于可见且可信的商品类型、颜色和形态等事实生成俄文标题、描述及标签；不会调用生图接口，也不会改造用户已经制作好的主图。填写有效水印文件时统一添加水印，水印留空时直接上传原成品图。
- “服务配置”支持保存多个 Ozon 店铺，每个店铺分别保存名称、Client-Id、Api-Key 和可选 HTTP 代理。旧版单店铺配置会自动作为“默认店铺”载入；在自动工作台选择本次上品店铺，任务队列会显示并固定绑定该店铺。
- “型号名称（针对合并为一张商品卡片）”必须人工填写，不允许 AI 或源商品覆盖。程序从 `/v1/description-category/attribute` 返回的当前类目属性中按中俄名称识别该字段，不写死属性 ID；需要合并的变体填写完全相同的型号名称，每个变体仍必须使用不同的 Offer ID，并填写真实的颜色、尺寸等差异属性。型号名称是自由文本，不能填写中文。
- 自动上架采用单工作线程顺序队列，避免多个产品同时争用浏览器、生图、OSS 和 Ozon 提交状态。上一件在后台运行时，工作台表单已经与运行任务隔离，可以立即填写并加入下一件产品，不会覆盖正在处理的内容。
- 任务队列提供“停止选中任务”，只影响表格中当前选中的一个产品，其他排队任务会继续运行。尚未开始的任务立即停止；正在运行的任务会在当前网络、生图或上传步骤返回后停止，并在调用 Ozon 商品导入前再次检查。停止后可打开“修复选中任务”修改再继续。若 Ozon 已返回导入任务 ID，该外部提交无法撤回，程序只停止后续查询和库存写入并要求到卖家后台处理。“清除已结束任务”会删除已完成、已停止和待修复记录及断点，但保留正在运行或排队的任务。
- 每件产品都会在解析、文案、图片、OSS、属性、草稿和提交后保存断点。某件失败后会停在“待修复”状态，队列自动继续处理后面的产品；选择失败行并点击“修复选中任务”，可重新绑定上品店铺，独立窗口会默认打开“商品属性修复”页，列出当前类目的全部属性、错误涉及项、必填缺失项和当前值。自由文本可直接修改，字典属性必须加载 Ozon 选项后选择；高级普通/组合属性 JSON 仍保留供特殊情况使用。保存后从受影响阶段继续，不会无条件重新做前面的生图和上传。
- 输入完整 Ozon 链接、纯数字 `Артикул`，或复制的 `Артикул: 2379505289`；程序会直达并校验该 SKU，只读取当前变体的标题、描述、商品参数和图库。
- 等待完整商品内容加载，并从描述区、独立标签/SEO 组件、短标签节点和页面商品 JSON 中读取以 `#` 开头的标签；自动排除 CSS 色值和页面锚点。原标签会显示在“搜索标签”，并作为文案生成依据保存到草稿。
- 按 Ozon 桌面页固定的左侧缩略图位置和页面坐标读取图库顺序，排除中央大图预览；自动把 `wc50/wc100/wc140` 地址提升为 `wc2000`，并按图片 ID、像素和视觉相似度去重最多 15 张高清原图。短边不足 600 像素的图片会被拒绝。
- 主图沿用参考程序的“两段式视觉分析 + 生图”策略：支持图片的分析 AI 先综合读取最多 6 张原图与 Ozon 页面事实，输出俄文海报文字白名单、版式方向和带图片序号/置信度的视觉事实；随后生图模型才生成海报。图片列表中单选一张作为主体参考，未选择时使用第 1 张；生图时仍只上传该主体图，避免混入其他变体。海报最多使用 1 个大标题与 3 个紧凑事实模块，其余原图仍作为附图保留。
- 跟卖模式的新主图和保留原内容的附图统一添加水印；附图不会重新生成。本地新品模式不重新生图，水印可选。
- 根据页面事实和俄罗斯买家的常见搜索意图生成俄文标题、描述和 25–30 个不重复搜索标签，不允许补造商品参数，也不在标签中加入品牌、货号、型号或尺寸等参数；主题标签统一格式化为 `#标签 #多词_标签`，以空格分隔。下划线只用于连接多词标签，每个标签（含 `#`）最多 30 个字符，保存草稿和提交前会再次校验。
- 文案服务必须使用 Chat Completions 完整地址，例如 `https://api.gpt.ge/v1/chat/completions`；若只填写域名或 `/v1`，程序会自动补全，并兼容代码块、说明文字和常见响应字段。
- 使用参考图生成主图时走 Images Edits 接口，例如 `https://www.micuapi.ai/v1/images/edits`；若只填写域名或 `/v1`，程序会自动补全，并在失败时显示真实 HTTP 状态和响应内容。
- 新主图使用 `1792x2400` 竖版尺寸与高质量档，强制一个完整产品、一个真实视角，并使用前景/产品/背景三层构图和手机端清晰可读的俄文图文层级；允许标题、事实卖点卡片、简洁图标与引导线，禁止多商品拼图、重复产品、未授权文字、虚构卖点和源卖家水印。我们自己的水印在生成后单独添加。
- 上传图片到阿里云 OSS。
- OSS 图片按 `对象前缀/YYYY-MM-DD/货号/` 分类。以货号 `WXZ003` 为例，文件依次命名为 `WXZ003主图.jpg`、`附图(1).jpg`、`附图(2).jpg` 等。同一商品在同一天重试上传会覆盖相同对象键，不再产生随机 UUID 文件；历史文件不会自动移动或删除，以免破坏已上架商品正在使用的图片链接。
- 从 Ozon Seller API 读取所有未禁用的类目和商品类型；按官方 `ZH_HANS` 语言读取简体中文名称，同时保留俄文名称和完整路径。刷新成功后完整类目树会保存到 `cache/ozon-categories.json`，以后启动程序直接从本地加载，无须每次联网读取；“加载/刷新类目”只用于首次建立缓存或主动同步 Ozon 更新。
- 自动工作台、类目属性页和任务修复页的类目输入框支持实时包含筛选。输入中文、俄文或路径中的任意关键词时，会立即显示所有包含这些关键词的本地候选并自动展开下拉列表。
- “服务配置”提供独立的产品视觉分析 AI 地址、密钥和模型；三项留空时复用文案 AI 配置，但复用模型必须支持多图输入。自动工作台中的类目完全由人工指定，AI 只映射该类目下的页面参数、经过校验的图片事实和字典候选，不会改变类目。
- 获取所选类目的全部实时中文属性并将必填项排在前面；后台同时读取俄文属性名称，用于把俄文商品页面事实准确映射到中文属性。
- 属性字典通过 `/v1/description-category/attribute/values` 和 `last_value_id` 读取全部分页值，并缓存到 `cache/ozon-dictionaries`。下次直接读取本地缓存，输入框只做本地筛选；可点击“刷新缓存”重新读取。只采用 Ozon 返回的 `dictionary_value_id`，支持字典多值属性。
- 品牌不加载、不搜索、也不缓存品牌库，始终锁定为“无品牌 / Нет бренда”（`dictionary_value_id=126745801`）；不能被人工、AI 或高级 JSON 改成其他品牌。“名称”属性默认使用生成的俄文标题，“#主题标签”属性默认使用格式化后的生成标签。
- 当前类目包含对应属性时，系统默认填写：“一个商品中的件数”=`1`、“原厂包装数量”=`1`、“保证”=`1 年`、“原产国”=`中国`。前两项按 Ozon 实时整数属性写入；“保证”和“原产国”必须从该类目的 Ozon 实时字典选择对应选项并携带真实 `dictionary_value_id`，不会写死字典 ID。如果在任务修复窗口的属性表或高级 JSON 中明确改成其他有效字典值，提交前不会覆盖人工修复。
- 若 Ozon 将“类型”标记为必填字典属性，且当前人工类目实时只返回一个合法选项，程序会自动写入该真实选项和 `dictionary_value_id`；有多个类型时仍交由 AI 或人工选择，不会猜测。修复窗口会把错误涉及项或缺失必填项自动排到首行并选中。
- 凡 Ozon 实时属性定义标记为字典/下拉选项，第一轮 AI 只生成内部语义检索词，不能作为属性值；程序随后读取 `/v1/description-category/attribute/values` 的完整本地缓存。500 项以内且文本量受控的字典会把全部真实选项交给第二轮 AI，大型字典只交给第二轮 AI 本地筛出的真实候选，并按请求大小分批。第二轮只能返回候选中的真实 `dictionary_value_id`。界面不会再把内部检索词显示成可选值；没有选中真实词时显示“未选择”。生成草稿和提交前还会再次校验每个字典 ID，不在当前选项中的文本或无效 ID 会被拒绝。
- 工作台根据采购成本、贴单费、目标 ROI、包装毛重和人工填写的标准佣金自动暂估售价；运费使用内置分段公式，广告费和货损率可调整，物流佣金为售价的 2%。程序不再按售价区间套用 12%/14%，也不读取 Ozon 平台佣金。勾选“FBP 核价”后，贴单费固定为 0 元，核价佣金在填写的标准佣金基础上减 1 个百分点（例如填写 14% 时按 13%），其余费用不变。商品净重写入类目中的“商品重量”属性，毛重与包装尺寸写入商品导入物流字段；毛重不能小于净重。折扣前价格填写 `0` 表示不设置折扣，非零时必须大于当前售价。
- 严格区分字典值和自由文本：带有效 `dictionary_value_id` 的 Ozon 中文下拉值允许提交；商品标题、描述、搜索标签及非字典文本属性如果包含中文，生成草稿前会被拦截并提示改成俄文。
- “AI 填写当前类目属性（不改类目）”只允许 AI 从 Ozon 返回的当前类目属性和字典候选中选择；程序会拒绝候选之外的属性 ID 和字典 ID。图片依据必须引用视觉分析结果中的图片序号且置信度不低于 85%，属性表“依据”列会显示图片编号、观察内容和置信度。品牌、型号、尺寸、重量、材质/成分、产地/制造商、认证、保证、包装数量/内容、容量及兼容性禁止仅凭图片自动填写。
- 类目改变后自动清空旧类目属性，提交前重新读取实时必填项，防止把上一类目的属性误带入商品。
- 生成本地草稿；必须二次确认才会真实创建商品。
- 商品导入成功后，程序直接使用任务中填写的标准佣金核验 ROI；FBP 使用“填写值减 1 个百分点”。通常导入价已经是计算结果，不会再次改价；若修复任务造成现有价格低于目标，程序才会通过 `/v1/product/import/prices` 提高一次售价，不会查询或等待平台重新计算佣金。ROI 达标后才向用户选择的 RFBS 仓库写入库存。
- 每件商品完成 Ozon 导入和 RFBS 库存写入后，程序自动创建或更新 `产品台账.xlsx`。同一店铺的同一货号会更新原行，新货号会追加新行；台账包含上品模式、核价模式、1688/Ozon 来源链接、售价、ROI、填写的标准佣金、实际核价佣金、费用、利润、重量、包装尺寸、类目、仓库、库存和任务 ID。本地新品的 Ozon 来源链接保持为空。旧版“Ozon 原始 RFBS 佣金”表头会自动迁移。打包版文件位于 EXE 同级的 `程序数据` 目录；若 Excel 正在占用该文件，任务会进入待修复状态，关闭 Excel 后继续任务即可安全补写。
- 页面读取/原图下载、文案 AI、产品视觉分析、图片生成、OSS 上传、实时类目/属性读取、导入状态查询和 RFBS 库存写入均带有限次数与退避等待。`POST /v3/product/import` 商品创建请求和 `/v1/product/import/prices` 改价请求不会因读取响应超时而盲目重发，以免重复提交；此时必须按 Offer ID 到卖家后台核对。支持单独配置 Ozon HTTP 代理。
- 当前编辑内容会每 15 秒自动保存；产品任务队列及每个任务的断点另存到 `auto_jobs.json`。重启后已完成和失败任务仍会显示；为防止无人确认时重复真实提交，重启时未结束任务会转为“待修复”，由你点击继续。任务只保存店铺 ID 和名称，所有店铺的 API 密钥仍只保存在 `config.json`，不会写入工作内容或队列文件。

## 启动

安装依赖：

```powershell
pip install -r requirements.txt
```

从项目根目录双击 `启动RFBS上品工具.bat`，或运行：

```powershell
python .\RFBS上品工具\main.py
```

## WB 上架

1. 在 WB 卖家后台创建个人 Token，授权 `Content`、`Prices and Discounts`、`Marketplace` 三个分类并开启读写权限；把 Token 填入“6. WB 上架”并测试权限。
2. 在“商品信息”选择“跟卖模式”或“本地新品模式”。跟卖模式解析 WB 链接/商品 ID；本地新品只选择自己准备的图片。填写卖家货号、标题、描述、包装规格，并在同一页填写采购成本、贴标费、目标利润率、人工佣金、广告费率、货损率和折扣；只有海外仓模式需要填写 CNY→RUB 汇率。程序不读取类目佣金。
3. 跨境发货按标准线路每 100g 向上计重：0.1–0.3kg 使用 `58 CNY/kg + 2 CNY/件`，0.4–20kg 使用 `43 CNY/kg + 8 CNY/件`。跨境店铺全程使用 CNY 核价，不读取 CNY→RUB 汇率。海外仓发货由人工填写的头程运费、海外仓操作费和 WB 尾程费组成；尾程采用 2026-07-15 版[官方物流规则](https://seller.wildberries.ru/instructions/ru/ru/material/logistics-types-and-cost-calculation?categoryId=fbw-model&goBackOption=prevRoute)，按包装体积、仓库物流系数和本地化指数计算，并以 RUB 反推满足目标利润率的折前整数标价。
4. `技术尺码`是卖家实际使用的规格标签（例如 `S`、`42`），`WB 尺码`是 WB 前台展示的标准尺码。无尺码商品两项都留空，程序仍会在 `sizes` 中上传商品条码。
5. “类目与属性”页提供 WB 内容 JSON。先读取当前子类目的实时属性，再可同步/编辑 JSON，或让已配置的图片 AI 根据所选商品图填写俄文标题、描述、尺码和类目属性。AI 只能使用 WB API 返回的属性 ID，尺寸和重量始终保留为人工独立输入。
6. 在“图片与库存”准备最多 30 张图片，第 1 张为主图。每张图片至少 700×900，最大 32 MB；填写库存并读取卖家仓库，然后开始上架。
7. WB 新卡片会异步同步到价格和仓库服务，最长可能需要 30 分钟。程序上传图片后会保存为等待状态，倒计时结束后点击“继续当前任务”即可设置价格和库存；不要为此重置任务或更换货号。
8. 完成后会把 WB 的 `nmID`、`chrtID`、子类目、售价、利润率、核价费用、重量、尺寸、仓库和库存写入同一个 `产品台账.xlsx`。同一 WB 店铺和卖家货号会更新原行。

Token 仅明文保存在本机程序数据目录的 `config.json`，不要发送给他人。`Sandbox` 仅测试 WB 内容与价格服务，程序不会在该模式写真实仓库库存。

## 工作内容自动保存

程序把当前工作自动保存到 `RFBS上品工具/workspace_state.json`，重新启动时无需再次解析和填写。你也可以在“5. 草稿与上架”点击“保存当前工作”立即保存。

- 自动保存内容：商品链接与页面信息、标题/描述/标签、尺寸重量价格、原图与处理后图片路径、视觉分析结果、OSS 图片地址、类目、属性、仓库和库存。
- 保存时机：每 15 秒、每项后台操作成功后、手工编辑图片或属性后，以及点击窗口关闭按钮时。
- 若首次升级时还没有自动保存文件，程序会尝试从 `输出/draft-*.json` 恢复最近草稿。
- `workspace_state.json` 不保存 Ozon、AI 或 OSS 密钥；这些密钥继续由 `config.json` 单独管理。

## 连续上架与错误修复

1. 在“自动工作台”先选择上品店铺，再填好第一件产品（包括该店 RFBS 仓库 ID 和人工型号名称），然后点击“加入队列并自动运行”。确认框会再次显示店铺名称；确认后，该产品立即成为绑定该店铺的独立任务并在后台运行。
2. 表单会清空 Ozon 链接、型号名称并生成新的 Offer ID；店铺、类目、价格、重量尺寸等常用值保留。可直接填写同店第二件商品；如需发往另一家店，先切换店铺并填写那家店的 RFBS 仓库 ID。正在运行的旧任务不会因切换而改变店铺。
3. 队列同一时刻只运行一件产品，后加入的产品显示“等待运行”。这不会影响你继续录入更多产品。
4. 某件产品报错时，该行显示“待修复”和真实错误信息，后面的等待任务仍会继续运行。
5. 若发现某件产品录入错误，先在队列表格选中它并点击“停止选中任务”；停止只作用于这一行。状态变成“已停止”后点击“修复选中任务”，在新窗口修正并继续。
6. 选中失败行也可直接点击“修复选中任务”。窗口默认显示“商品属性修复”：红色行表示错误涉及项或缺失必填项；选中自由文本属性后直接保存文本，选中字典属性后点击“加载全部选项”并采用 Ozon 返回值。修正完成后点击“保存修复并继续运行”。
7. 如果只修正价格、尺寸、文案或属性，程序从草稿/提交附近继续；改变类目或净重时重新填写属性；改变源 Ozon 链接时才从商品解析重新开始。
8. 如果 Ozon 已返回导入任务 ID，但查询状态或写库存时失败，继续任务会沿用该任务 ID 查询，不会盲目再次调用商品导入接口。

队列文件位于 `RFBS上品工具/auto_jobs.json`，包含产品输入、处理断点和错误信息，但不包含服务密钥。不要在程序运行时手工编辑该文件。

## 推荐测试顺序

1. 在“2. 服务配置”点击“新建店铺”，填写店铺名称、Client-Id、Api-Key 和可选代理，点击“保存/更新店铺”并测试连接；有几家店就分别保存几次。再保存文案 AI、生图、视觉分析 AI 和 OSS 配置；视觉分析三项留空时复用文案 AI，但模型必须支持图片。在“3. 商品与图片”选择一次水印，在“5. 草稿与上架”读取相应店铺的 RFBS 仓库并设置默认库存。
2. 首次使用新版时返回“1. 自动工作台”点击一次“加载/刷新类目”来建立本地缓存；后续启动无需重复加载。直接在类目框输入中文或俄文关键词，从实时筛选出的候选中人工选择准确类目。仅当 Ozon 类目发生变化时再主动刷新。
3. 选择上品模式。跟卖模式填写 Ozon 链接/商品 ID；本地新品模式点击“选择图片”，按选择顺序把主图放在第 1 张，来源链接无需填写，Offer ID 由程序自动生成。继续填写型号名称、采购成本、贴单费、目标 ROI、标准佣金、折扣前价格、商品净重、包装毛重及包装长宽高，确认自动售价和费用预估。使用 FBP 核价时勾选“FBP 核价”，程序会把贴单费锁定为 0 并把填写佣金降低 1 个百分点。需要合并的测试变体使用相同型号名称、不同 Offer ID。
4. 在自动工作台选择店铺并填写该店 RFBS 仓库 ID，点击“加入队列并自动运行”，核对确认框中的店铺、价格、重量、尺寸和类目后确认真实上架；随后可切换或保留店铺，继续填写第二件产品并加入队列。
5. 观察队列表格、9 段进度和“5. 草稿与上架”的日志；临时网络、AI、图片或 OSS 故障会自动重试。业务校验错误不会无意义重试。
6. 为验证修复流程，可在测试商品上临时填写一个无效的必填属性值；任务进入“待修复”后，选中该行打开修复窗口，改正并继续。
7. 若提示缺少 Ozon 必填属性，可在修复窗口或“4. 类目与属性”检查缺项；程序不会为了完成流程而伪造页面不存在的材质、认证或许可信息。
8. 成功后检查 `输出/draft-*.json`、`输出/submitted-*.json` 和 `产品台账.xlsx`，再到 Ozon 卖家后台按 Offer ID 核对审核、图片、价格和 RFBS 可售状态。

## Ozon 官方接口流程

核对日期：2026-08-10。官方入口：https://docs.ozon.ru/api/seller/

1. `POST /v1/description-category/tree`
2. `POST /v1/description-category/attribute`
3. `POST /v1/description-category/attribute/values`（按 `last_value_id` 读取全部分页并缓存）
4. `POST /v3/product/import`
5. `POST /v1/product/import/info`
6. `POST /v1/product/import/prices`（仅在修复后的当前售价未达到目标 ROI 时调用）
7. `POST /v2/warehouse/list`
8. `POST /v2/products/stocks`

Ozon 会更新接口和属性规则。程序不设置静态类目白名单，但最终能否 RFBS 销售仍取决于卖家账户、实时类目状态、商品认证/标识要求、尺寸重量和仓库物流配置。

## Ozon 连接超时

错误中出现 `api-seller.ozon.ru:443`、`ConnectTimeoutError` 或 `Max retries exceeded`，表示程序尚未连接到 Ozon API，并非商品 JSON、图片或属性错误。

1. 先在“服务配置”点击“测试 Ozon 连接”。
2. 若电脑使用代理/VPN，查找它的 **HTTP 代理端口**，把 `http://127.0.0.1:端口` 填入“Ozon HTTP代理（可选）”，保存后重试。不要把 SOCKS 端口填入该字段。
3. 若不使用代理，保持该字段为空，并检查 DNS、防火墙和当前网络是否能访问 `api-seller.ozon.ru:443`。
4. 如果错误是“已连接但等待响应超时”，先按 Offer ID 到卖家后台查询；程序不会自动重发导入请求，避免重复创建。
