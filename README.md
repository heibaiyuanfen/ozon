# Ozon 广告与销量分析（本地 MVP）

> 完整项目结构、业务逻辑、重构进度和持续更新记录：[PROJECT_ARCHITECTURE_AND_MIGRATION.md](PROJECT_ARCHITECTURE_AND_MIGRATION.md)

这是一个面向 Ozon 俄罗斯本土店的本地桌面分析工具。第一版用于验证数据结构和交互流程，后续可以继续增加指标、自动同步、利润核算和更细的广告诊断。

## 已有功能

- WB 跨境独立工作台：从主界面的紫色入口打开，与 Ozon 店铺和数据库完全隔离；配置独立的 WB API Token、店铺名、人民币/卢布汇率和飞书机器人。实时订单读取 WB Statistics Orders，本地按 `srid` 去重缓存；广告按“日期 + 广告活动 ID + WB nmId”精确归因到单品，不把活动总费用平均分摊。
- WB 利润初算：逐日展示销量、销售额、精确商品广告费、采购成本、暂估平台费、暂估物流和预计利润。仓库名单与地址首次联网读取后保存到 WB 本地数据库；东莞仓暂按轻小件 `重量×58+2`、普通件 `重量×43+8`，俄罗斯海外仓暂按 `8 + MAX(体积升-1, 0)×2` 估算，完整运价表提供后可替换为最终规则。
- WB 周利润飞书卡片：预览任意完整周并由用户手动发送到群，卡片包含 WB 店铺名、销量、销售额、广告、平台费、采购、物流、预计利润及缺失成本数量，不自动向飞书推送。
- 多店铺隔离：左侧可新增、重命名并切换本土店/跨境店；每个店铺使用新版 `data-next/` 下的独立 SQLite 数据库和独立 API 凭证，SKU、销量、广告、财务、库存与成本不会混在一起。首次升级只执行一次 SQLite 一致性快照迁移，随后新版不再连接旧版 `data/` 数据库。允许修改店铺类型；变更类型时自动启用新的独立数据库，旧数据库保留，避免串库。
- 产品成本：独立页面只展示货号与 Ozon SKU，不展示冗长商品名。采购成本、头程、长宽高、重量均按 SKU 保留；采购和头程以人民币录入，店铺汇率采用“1 CNY = X RUB”，改汇率后月度盈亏实时重算。支持 `GJYB001` 等系列模糊匹配和批量统一成本。
- 跨境店利润：只有当前店铺类型为“跨境店”时才读取该店独立缓存；本土店页面保持为空。默认采用实时预估口径：Seller Analytics 下单销售额减去历史已结算数据推导的 SKU 佣金率、全店收单费率、采购成本和预估跨境运费；全店广告只在期间/周度汇总扣除。Finance 已结算净额单独保留为对账列，不再因未签收订单尚无结算收入而把当天利润误判为亏损。每个产品直接显示计算公式，搜索在内存缓存中完成。
- 命名 API 配置中心：API 设置页直接显示“API 配置名称、店铺名称、店铺类型”，编辑区固定可见，可新增、模糊搜索、立即切换、重命名和修改类型；新配置创建后自动切换并进入凭证填写页。支持一次导出/导入全部命名店铺 API，导入后在新电脑用 DPAPI 重新加密；迁移文件含明文密钥，用完应删除。
- 跨境上品联动：可一键启动 RFBS 上品工具，启动前自动选中当前跨境店 Seller API；同时连接其 `产品台账.xlsx`，把采购成本、重量、包装长宽高同步到当前跨境店。
- 跨境履约对账：从本地 Finance 缓存的 `posting.delivery_schema` 区分 FBP、FBS/realFBS 和 WHD，不为分类重复调用 API。销量与销售额仍以 Seller Analytics 为准。
- 现代化界面：统一深色工作台侧栏、轻量卡片、筛选工具条、数据表格、按钮与状态栏样式；切换页面时仅延迟刷新当前页，搜索输入合并为防抖刷新，避免每个按键重算全部大表。
- 经营总览：销售额、下单量、广告花费、ROAS、ACOS、TACOS、CTR、退货与产品取消率；支持近 7 天、近 30 天、本月、上月和自定义日期，趋势图可切换“销售额”与“销量”，鼠标悬停可查看每日精确值。
- 广告分析：按活动查看曝光、点击、订单、花费、广告销售额、ROAS 和 ACOS，并可按活动、状态、计费方式、最低花费和最高 ACOS 组合筛选。
- 商品销量：同时显示商家货号与 Ozon SKU，并查看下单、妥投、退货、取消、取消率、浏览、加购、转化和销售额；没有权限或尚未同步的字段显示“—”，不再冒充真实的 0。
- AI 分析：全店模式发送当前日期范围内的汇总、趋势和商品/广告 Top 20；单商品模式发送“全店活动级广告效率汇总 + 所选 SKU 的本地广告、业务明细和库存集群”。AI 页面不会请求 Ozon，只读取数据中心已同步的本地缓存；优先使用精确 SKU 明细，没有时仅匹配名称明确含 SKU/货号的专属活动并标注为活动级推算。结果可导出为排版后的 Word 或 PDF 业务报告。
- 周报：按周一至周日汇总销售额、销量、广告花费、广告订单、广告单占比和 ACoTS，并与上一完整周做环比；可手动拉取，软件打开时会自动检查并补齐最新完整周。
- 库存管理：首页按货号与 Ozon SKU 紧凑展示可售库存、在途、已申请、日/月估销量、建议补货、计划补货集群和预计可售天数，不显示占用空间的商品名称列。双击 SKU 后弹出全部宏区集群详情，显示中俄集群名、IDC 和各集群库存；可逐行修改计划补货、一键采用建议并导出带公式的 Excel。
- 库存同步容错：Ozon 返回重复的 SKU/仓库快照时会先去重合并，仓库 ID 缺失的虚拟集群使用稳定集群键保存；不会因唯一键冲突中断整批库存同步，也不会把重复库存相加造成虚高。
- 约仓计划：自动读取库存管理中已保存且数量大于 0 的集群计划。选择直送/越库并双击集群后，可分步搜索发货点、创建并校验 Ozon 草稿、选择目的仓与当地时段，再二次确认创建真实供应申请；所有远程写请求仅发送一次，不自动重试。发货点按当前店铺缓存，普通搜索不再重复请求，点击“联网刷新”才更新缓存；越库草稿固定发送有效的 `CROSS_DOCK` 仓库类型，避免 Ozon 返回默认枚举 `0` 后造成 HTTP 400。
- 可输入下拉框与模糊搜索：日期预设、广告筛选、商品、供应方式、地址和约仓向导等下拉框均可直接输入并自动展开匹配项；输入 `GJYB` 会列出所有包含该文字的货号/SKU。销量、广告、库存等列表搜索也会即时显示全部匹配行。
- 飞书同步：以 SKU 为唯一键，把单件成本、单件头程和备注从多维表格读回本地，再把本地商品增量写回飞书；支持周报表按周期更新和机器人群消息。可安装 Windows 后台计划任务，每天 09:00 检查一次并确保同一周只发送一次。
- 月度盈亏表：仅对俄罗斯本土店开放，按 SKU 汇总销售额、Finance 平台净回款、佣金、物流、退货、广告及各类应计费用。增加可编辑 USN 税率与回款手续费，分别显示税前与税后利润；默认 USN 收入制 6% 只是预估，VAT 与地区优惠需按会计口径修改。
- 本土产品利润表：使用实时 Seller 订单金额、本地缓存的精确 SKU 广告报告、Finance 历史费率与产品成本估算税前/税后利润。显示 SKU 广告费占全店广告费、广告销售占比、每广告订单平均费用、配送起始/目的地及基础配送费估算；双击 SKU 查看逐日明细和完整公式。
- API 设置：分别配置 Seller API、Performance API 与 OpenAI 兼容中转站；飞书凭证在独立的“飞书同步”页面配置。
- 数据中心：手动同步、演示数据、同步日志和 CSV 导出。
- 演示数据可独立删除，不影响从真实 API 同步的数据。
- 快速广告同步：默认调用 Performance `statistics/daily/json` 即时接口，一次读取日期范围内的活动级每日数据，不再逐批创建异步报告。
- 完整运行日志：保存并显示认证、请求接口、返回解析、汇总校验、写入本地数据库和错误详情。
- 字段诊断：兼容活动日报的 `campaignId`、`id/title` 和嵌套活动字段；未知结构会记录原始字段与样例并将任务标记为失败。
- 金额字段：兼容每日统计实际返回的 `moneySpent`（广告花费）和 `ordersMoney`（广告销售额）。
- 稳定同步：支持 Ozon 限频等待、HTTP 429/TLS 临时错误自动重试，以及取消同步任务；Seller Analytics 最多只等待并重试一次，避免卡住数分钟。
- Seller 智能增量：销量分析与财务流水已有历史缓存时只重取最后一个缓存日期并补齐其后的缺失日期；已核验的历史范围不再请求，当天快照 30 分钟内复用，Analytics 限频冷却时间会跨应用重启保存。
- Seller 数据补全：商品目录同步货号；退货使用财务确认记录并按原始下单日期估算，不再把物流退货池中的取消/拒收全部算作退货；当当前 API 权限未返回后台原生 `returns` 时，界面以“≈”明确标记辅助口径。新版 FBO/FBS 发货列表同步商品取消件数并计算取消率。同步日志同时记录 `/v1/analytics/data` 实际返回与被省略的指标；当前密钥未返回浏览/加购时界面保留“—”。
- 本地存储：新版使用独立 SQLite 数据根目录 `data-next/`；默认本土店数据库为 `data-next/ozon_next_default.db`。旧版 `data/ozon_analytics.db` 仅保留备份，不参与新版运行时读写。
- 凭证保护：API Secret 和 Seller API Key 使用 Windows DPAPI 按当前用户加密。
- AI 隐私：只有主动点击“开始分析”时才会向配置的中转站发送数据；全店模式限 Top 20，单商品模式只附加店铺整体广告效率和所选 SKU 的本地业务/广告数据。AI 页面不调用 Ozon，不会发送其他 SKU 明细、Ozon API 凭证或本地数据库文件。

## 启动方法

双击 `run_app.bat`。

如果启动失败或需要查看报错，双击 `run_debug.bat`。

开发环境也可以直接运行：

```powershell
python main.py
```

需要 Python 3.11 或更高版本。双击 `run_app.bat` 会优先使用已包含 Word/PDF 组件的本地运行时；若直接使用自己的 Python，请先执行 `python -m pip install -r requirements.txt`。

## Windows 打包

右键 `build_exe.ps1` 并选择“使用 PowerShell 运行”，会生成：

- `release/OzonAnalytics_v0.15.3/OzonAnalytics.exe`
- `release/OzonAnalytics_v0.15.3.zip`

打包脚本会生成应用图标、构建单文件 EXE、复制当前本地数据库，并在 EXE 内执行界面启动及 Word/PDF/补货 Excel 导出烟雾测试。便携包中的 `data` 文件夹包含店铺数据和经 DPAPI 加密的凭证，不应直接发送给其他人。

## 首次体验

1. 打开“数据中心”。
2. 点击“生成演示数据”。
3. 返回“经营总览”“广告分析”和“商品销量”查看效果。
4. 在“API 设置”填入真实凭证并保存。
5. 在“数据中心”选择日期后同步。

## API 凭证

Seller API 使用：

- `Seller Client ID`
- `Seller API Key`

Performance API 使用：

- `Performance Client ID`
- `Performance Client Secret`

这两套凭证互不通用。

WB 跨境工作台使用一枚独立 WB API Token。当前读取范围需要令牌具备“统计报表、推广、商品/仓库”对应的只读权限；WB 数据只写入 `data/wb/wb_analytics.db`，不会读取或混入 Ozon 店铺数据库。

AI 中转站使用：

- `API Base URL`：可填写 `https://api.gpt.ge/v1`，也兼容完整的 `/v1/chat/completions` 地址
- `API Key`
- `模型名称`：例如 `gpt-5.6-terra`，以中转站实际支持的模型为准

AI 接口按 OpenAI Chat Completions 兼容格式调用。API Key 同样使用 Windows DPAPI 加密保存在本机。

## 飞书配置

1. 在飞书开放平台创建企业自建应用，添加机器人能力。
2. 为应用开通多维表格查看/编辑权限和“以应用的身份发消息”权限，发布应用版本。
3. 把应用添加为目标多维表格的协作者，并把机器人加入接收周报的群聊。
4. 在软件“飞书同步”中填写 App ID、App Secret、App Token、商品表/周报表 Table ID 和群 Chat ID。
5. 点击“测试连接”，然后执行商品双向同步或周报写表并发群。
6. 需要软件关闭后继续运行时，点击“安装后台计划任务”。移动 EXE 所在目录后需重新安装该任务。

商品表会自动补齐 `SKU`、`货号`、`商品名称`、`单件成本`、`单件头程`、`备注`、`本地更新时间` 字段。周报表会自动补齐周期、核心指标和环比字段。App Secret 与其他 API 密钥一样使用 Windows DPAPI 加密。

## 当前版本的边界

- Ozon 会持续调整 API 版本和广告报告字段。Performance 报告解析层已兼容常见 JSON/CSV 字段，但首次真实连接后仍应按店铺返回内容校准。
- “快速同步广告”把广告活动级每日统计保存到本地，包含曝光、点击、花费、订单和广告销售额。AI 页面只读这份缓存：单商品有精确 SKU 缓存时优先使用；否则仅用活动名明确匹配该 SKU/货号的专属活动做活动级推算，通用活动不会被强行归因。
- Seller `/v1/analytics/data` 的权限、可用指标和历史周期可能受店铺权限或订阅限制。
- AI 输出由模型生成，只作为经营辅助建议；结论质量取决于所选日期范围内本地数据的完整度。
- 软件打开时会按小时检查最新完整周；安装 Windows 后台计划任务后，软件关闭时也会每天 09:00 补检。电脑必须开机且当前 Windows 用户能运行该任务；首次更新或缓存缺失时仍需有效的 Seller / Performance 凭证。
- 月度盈亏是初版经营核算：产品成本与头程需要在页面中维护；无法可靠归因到 SKU 的活动级广告花费暂不强行分摊。
- 暂未把财务流水展示成独立页面，但月度盈亏已直接使用同步到本地数据库的 Finance 流水计算平台净回款和费用。
- 建议补货量是本地计划公式：`MAX(0, 向上取整(集群日均销量 × 目标天数 - 可售库存 - 在途 - 已申请))`，不是 Ozon 后台直接返回的官方建议值。库存快照以 Ozon 接口更新时间为准。
- 新约仓向导目前按“单个 SKU × 单个集群”创建直送或越库草稿，并支持目的仓、时段和供应申请提交。后续仍需继续补充多 SKU/多集群合单、包装、货运和标签流程。任何网络超时都不会自动重试写请求，应先到 Ozon 后台核对是否已受理。

## 代码结构

```text
main.py                  程序入口
ozon_app/ui.py           Tkinter 桌面界面
ozon_app/api.py          Seller / Performance API 客户端
ozon_app/database.py     SQLite 数据模型、查询和演示数据
ozon_app/services.py     同步业务流程
ozon_app/exports.py      AI Word/PDF 与带公式补货 Excel 报告生成
ozon_app/feishu.py       飞书认证、多维表格与群消息客户端
ozon_app/listing_ledger.py  RFBS 上品工具台账读取与店铺过滤
ozon_app/listing_integration.py  跨境 Seller API 切换与上品工具启动
ozon_app/scheduler.py    Windows 后台周报计划任务
ozon_app/secrets.py      Windows 凭证加密
ozon_app/config.py       应用常量与配色
tests/                   无网络单元测试
```
